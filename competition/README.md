# Trace the Ace — Tutoring Outcomes Prediction Challenge

Working material for the [Trace the Ace challenge](https://platform.k12-ai-infrastructure.org/competitions/3/tutoring-outcomes/)
on the K-12 AI Infrastructure Platform: predict, from a tutor–student session
transcript alone, whether the student then answers a follow-up question on a
given learning objective correctly. Scored by **log loss**. Code-execution
format. **Submissions close August 27.**

## Layout

```
submission_src/          <- packaged as submission.zip; main.py MUST be at its root
  main.py                   runtime entrypoint; cannot crash, always writes submission.csv
  src/features.py           transcript -> 76 pedagogically legible features
  src/model.py              portable model bundle, prior fallback, log-loss clipping
  model/                    trained bundle lands here (git-ignored)
training/
  train.py                  GroupKFold CV, out-of-fold target encoding, leakage diagnostic
  preflight.py              pre-upload validator: replicates every platform check locally
  make_synthetic_data.py    fake dataset for smoke-testing the pipeline end to end
tests/test_contract.py    <- asserts the submission survives every failure path
```

## Quickstart

```sh
# 0. Smoke-test the whole pipeline with no competition data at all
python training/make_synthetic_data.py --out /tmp/syn --n-sessions 400
python training/train.py --data-dir /tmp/syn

# 1. Train on the real data
python training/train.py --data-dir /path/to/competition/data

# 2. Package (from the runtime repo clone, with submission_src/ copied in)
just pack-submission
just check-submission

# 3. Validate before spending a submission
python training/preflight.py --zip submission/submission.zip --data-dir data-demo

# 4. Authoritative check, in the real competition image
just pull && just test-submission
```

## Verified behaviour

Run against the official demo data with a trained bundle, all under a faithful
simulation of `runtime/entrypoint.sh`:

- Valid `submission.csv`, correct columns, `response_id` order identical to
  `submission_format.csv`, all probabilities strictly inside `(0, 1)`.
- **Exit 0 and a valid submission under every failure path tested**: corrupt
  bundle, one transcript missing, all transcripts missing, `src/` deleted,
  `test_features.csv` missing, malformed transcript. On a code-execution
  platform a non-zero exit discards the run entirely, so this matters more than
  any feature.
- Synthetic benchmark, grouped CV log loss: **0.58359** vs 0.67545 for the
  per-objective prior and 0.69315 for the constant-0.5 submission that the
  unmodified official example produces.

`preflight.py` was checked against both failure shapes it exists to catch: it
FAILs a nested zip (which the platform's own check accepts and then crashes on)
and WARNs on a constant-probability submission.

## Caveat on the numbers

The scores above are on **synthetic data generated by
`training/make_synthetic_data.py`**, not on competition data. They demonstrate
that the pipeline works end to end and that the harness detects leakage; they
say nothing about where this lands on the real leaderboard. The synthetic
transcripts are not a model of real tutoring and must not be used to draw any
conclusion about tutoring.

Competition data is not in this repository and must not be committed to it.
